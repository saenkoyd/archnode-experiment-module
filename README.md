# Модуль анализа и сравнения методов синтеза архитектуры

Версия 1.0.

Программный модуль предназначен для анализа и сравнительной оценки методов формирования и выбора архитектурных решений сложных программных систем. Он выполняет полный вычислительный процесс: от исходных значений элементов до локального многокритериального отбора, сборки совместимых состояний, межуровневого перерасчёта и выбора архитектурной альтернативы.

Для демонстрации и проверки функций в состав поставки включены один полностью раскрытый контрольный пример и 30 базовых синтетических наборов, рассмотренных в четырёх режимах, то есть 120 случаев «набор — режим». Эти данные образуют встроенный сценарий сравнительного анализа, но не ограничивают назначение программного модуля.

## Воспроизведение

Для полного анализа из корня репозитория выполнить одну команду:

```bash
python3 run_analysis.py
```

Для запуска только основного вычислительного ядра:

```bash
python3 run_experiment.py
```

Внешние пакеты и доступ к сети не требуются; используется только стандартная библиотека Python. Скрипт заново формирует все файлы каталога `results/` и завершается строкой `all reproducibility assertions passed`. На использованной машине полный расчёт вместе с анализом чувствительности занимает около одной минуты.

Два последовательных контрольных запуска сформировали побайтно одинаковые 15 файлов результатов. SHA-256 от упорядоченного списка их SHA-256 равен `ac593f824d3de78035cf9d775b828b8ef3054f0fe8a9b92ce250cd8ff6ff9df4`.

Главный генератор зафиксирован значением `master_seed = 20260827`. Для каждого номера повторения один и тот же seed, набор альтернатив и контрольная нагрузка применяются во всех четырёх режимах; внутри одной задачи все методы получают строго один экземпляр. Это позволяет выполнять парные сравнения без смешения межзадачной вариации и эффекта режима.

## Состав пакета

Исходные файлы:

- `run_analysis.py` — единая точка запуска полного сравнительного анализа;
- `product.json` — название, версия и технические сведения о программном продукте;
- `config.json` — веса, seed, режимы, допуск и предел итераций;
- `inputs/criterion_passports.csv` — паспорта трёх критериев, функции соответствия и веса;
- `inputs/control_vertices.csv` — исходные значения `x` двух вершин каждой альтернативы и веса структурной роли `lambda`;
- `inputs/control_alternatives.csv` — ожидаемые значения `F`, сигнатуры и справочные признаки;
- `inputs/control_certificates.csv` — пять булевых проверок каждого сертификата замены и итоговое значение `R`;
- `inputs/control_compatibility.csv` — явная совместимость всех 27 комбинаций;
- `inputs/control_states.csv` — параметры трассировки и внецелевые синтетические исходы пяти допустимых состояний;
- `inputs/control_expectations.json` — машинно проверяемые ожидаемые результаты контрольного примера.

Скрипт и результаты:

- `run_experiment.py` — генератор, реализации пяти процедур, расчёт метрик и assertions;
- `results/control_vertices_calculated.csv` — переход `x -> p=mu(x)`;
- `results/control_alternatives_calculated.csv` — рассчитанные `F`, `Q0`, локальные фронты и передаваемые множества;
- `results/control_certificates_calculated.csv` — перепроверка пяти условий и `R`;
- `results/control_positions.csv` — начальные и установившиеся значения позиций оценки;
- `results/control_iteration_trace.csv` — остаток каждой итерации для всех пяти состояний;
- `results/control_states_raw.csv` — полный расчёт пяти допустимых состояний;
- `results/batch_instances.csv` и `batch_tasks.csv` — сгенерированные задачи и их параметры;
- `results/batch_raw.csv` — 600 запусков процедур и внецелевые holdout-исходы выбранных состояний;
- `results/batch_summary.csv` — агрегированные метрики, IQR и bootstrap-интервалы;
- `results/batch_pairwise.csv` — парные описательные сравнения полного метода с упрощёнными процедурами;
- `results/batch_sensitivity_raw.csv` и `batch_sensitivity_summary.csv` — анализ чувствительности;
- `results/summary.json` — машиночитаемый сводный протокол и статусы assertions;
- `results/manuscript_tables.md` — компактные таблицы для переноса в текст диссертации.

## Контрольный пример 3 × 3 × 3

Для каждого из уровней `A`, `B`, `C` заданы три альтернативы, две вершины (`core`, `boundary`) и три критерия. Функция соответствия в контрольном примере тождественна: `p=mu(x)=x`; структурные веса вершин равны 0,6 и 0,4. Скрипт независимо вычисляет

```text
x -> p -> lambda -> F -> Q0 -> локальный фронт -> R
  -> совместимое полное состояние -> итерационный перерасчёт -> Q.
```

Получены и проверены следующие значения:

| Результат | Значение |
|---|---:|
| исходное пространство | 27 комбинаций |
| пространство после сертифицированного сокращения | 18 комбинаций, сокращение 33,33 % |
| допустимые состояния полного перебора | 5 |
| допустимые состояния после безопасного сокращения | 3, потенциальное сокращение числа полных оценок 40 % |
| глобальный фронт обоих способов | `S1`, `S2`, `S3` |
| локально-жадный выбор | `A1+B2+C3`, несовместим |
| выбор аддитивной свёртки без трассировки | `S3`, `Q0=0,771400` |
| небезопасный Парето-отсев | `S1`, полнота глобального фронта 1/3 |
| полный предложенный процесс | `S2`, `Q=0,777383` |
| полный перебор по той же модели | `S2`, `Q=0,777383` |

Для `S2` предварительная оценка равна 0,717333. После синхронного межуровневого перерасчёта она становится 0,777383; сходимость достигается за 28 итераций при остатке меньше `1e-12`. Внецелевая синтетическая holdout-полезность `S2` равна 0,722341, а `S3` — 0,666054. Полезность рассчитывается из p95 задержки, доли ошибок, времени восстановления и ресурсного индекса нелинейной геометрической свёрткой и не входит непосредственно в `Q`, но связана с параметрами того же генератора.

## Пакетная серия

Каждая задача содержит четыре уровня и восемь вариантов на уровень, то есть 4096 исходных комбинаций. На каждом уровне один доминируемый вариант имеет полный сертификат безопасной замены, а другой доминируемый вариант сохраняется из-за отсутствия такого сертификата. Выполнено по 30 повторений в режимах:

- `no` — межуровневое влияние отключено, отрицательный контроль;
- `medium` — умеренное влияние;
- `strong` — сильное влияние;
- `conflict` — влияние сочетается с дополнительными ограничениями совместимости.

Сравниваются пять процедур:

1. `local-greedy` независимо выбирает максимальный `Q0` каждого уровня и затем только проверяет совместимость.
2. `feasible-additive-no-trace` перебирает допустимые состояния и выбирает максимум средней предварительной оценки без межуровневого перерасчёта.
3. `unsafe-pareto` без сертификата удаляет все локально доминируемые варианты, после чего применяет полную оценку к оставшимся состояниям.
4. `full-method` удаляет вариант только при сертификате, собирает состояния и выполняет полную оценку.
5. `oracle-full-model` перебирает все допустимые состояния по той же полной модели. Это эталон проверки корректности сокращения поиска, а не независимая «истина» о качестве архитектуры.

Ключевые результаты серии:

| Режим | Top-1 без трассировки | Top-1 полного метода | Regret без трассировки | Regret полного метода | Парное снижение regret, bootstrap 95 % CI |
|---|---:|---:|---:|---:|---:|
| `no` | 1,000 | 1,000 | 0,189623 | 0,189623 | 0,000000 [0,000000; 0,000000] |
| `medium` | 0,8667 | 1,000 | 0,189623 | 0,166686 | 0,022937 [0,000908; 0,051074] |
| `strong` | 0,4333 | 1,000 | 0,189623 | 0,108016 | 0,081607 [0,029730; 0,136133] |
| `conflict` | 0,5667 | 1,000 | 0,167407 | 0,095698 | 0,071709 [0,017544; 0,132074] |

В отрицательном контроле полный процесс и аддитивная процедура совпали в 30 задачах из 30. Безопасно сокращённый глобальный фронт буквально совпал с фронтом полного перебора во всех 120 случаях; совпали также все 120 top-1 решений. Размер пространства кандидатов полного метода составил 2401 вместо 4096, то есть уменьшился на 41,38 %. Расчётное число полных оценок допустимых состояний, которые потребовались бы при самостоятельном выполнении сокращённой процедуры, ниже референтного на 36,52 % в режимах `no`, `medium`, `strong` и на 35,22 % в режиме `conflict`. Текущий скрипт сначала рассчитывает референтное множество и лишь затем фильтрует уже рассчитанные объекты, поэтому эти доли не являются измеренным ускорением фактического запуска.

Для каждой задачи с помощью отдельного seed сформировано 40 контрольных значений нагрузки, не участвующих в выборе. Для выбранного состояния в `batch_raw.csv` сохранены p95 задержки, доля ошибок, время восстановления и ресурсный индекс. Нормированный regret вычисляется относительно лучшей и худшей внецелевой синтетической полезности среди допустимых состояний. Она не входит непосредственно в `Q`, но латентные характеристики и согласованность интерфейсов связаны с тем же генератором, поэтому это проверка согласованности, а не независимая внешняя валидация. Для недопустимого выбора regret не определён и оставлен пустым; доля недопустимых рекомендаций учитывается только показателем feasibility. Полнота Парето-фронта приводится только для процедур, которые действительно формируют фронт, но не для single-choice baselines.

## Чувствительность

Для каждой задачи выполнено 20 дополнительных расчётов полного метода: каждый из трёх весов отдельно изменялся на ±10 % и ±20 % с последующей перенормировкой; отдельно изменялись `rho` и масштаб трассировочного влияния. Всего выполнено 2400 возмущённых расчётов. Сводная доля сценарно-взвешенная: изменения трёх весов представлены 360 расчётами на режим, а `rho` и масштаба — по 120; в режиме `no` изменения двух нулевых коэффициентов тривиально оставляют их нулевыми. Доля сохранения исходного выбора среди всех 600 сценариев режима составила:

| Режим | Устойчивость выбора |
|---|---:|
| `no` | 0,910000 |
| `medium` | 0,881667 |
| `strong` | 0,933333 |
| `conflict` | 0,885000 |

Детализация по коэффициенту и величине возмущения находится в `batch_sensitivity_summary.csv`.

## Проверяемые утверждения и ограничения

Встроенные assertions подтверждают арифметику контрольного примера, полный переход от `x` до `Q`, логику пятикомпонентного сертификата, сходимость оператора, совпадение полного фронта и top-1 после безопасного сокращения, а также совпадение с аддитивной процедурой при отключённой трассировке.

Эксперимент синтетический. Он проверяет внутреннюю корректность, воспроизводимость, условия безопасного сокращения и поведение процедур при контролируемом межуровневом влиянии, но не оценивает сам по себе экономический эффект, полноту экспертных критериев или переносимость численных порогов на конкретную организацию. `oracle-full-model` остаётся эталоном внутри исследуемой модели. Операционные исходы не входят непосредственно в формулу `Q`, но коррелированы с частью параметров того же генератора; поэтому статистические интервалы характеризуют только заданное семейство задач. Парные bootstrap-интервалы являются описательной оценкой неопределённости по 30 синтетическим экземплярам внутри режима, а не доказательством универсального превосходства метода.
